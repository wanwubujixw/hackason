# 黑客松现场演示脚本（3~5 分钟）

> **本文件由 E 模块和 A 模块一起完善**。演示前把流程背熟，不要现场翻文档。
> 目标：3~5 分钟内让评委看完核心价值。

---

## 开场（30 秒）

> （先展示首页屏幕，"解忧慢递邮局"标题）

**你**：
"评委好，我们的项目叫「解忧慢递邮局」。这是一个面向大学生的轻量情绪陪伴应用。
当我们在校园里感到累了、烦躁了或者迷茫了，只要花一分钟选一下现在的心情，
我们会给你一封校园回信，并推荐一个适合此刻的校园地点。

我们的技术栈很轻量——纯静态 Web，不需要后端、不需要大模型 API，所有推荐逻辑和文案都是本地的。
两天内从零搭起来，现在可以跑通完整的情绪闭环。"

---

## 演示核心流程（2 分钟）

> （从头到尾走一遍 MVP 流程，语速稍快但要清晰）

**步骤 1：选心情**（首页 → 点心情按钮）
- 选"疲惫 😴"

**步骤 2：选时间和偏好**
- 选"只有 15 分钟"、"安静"、"想独处"

**步骤 3：看推荐结果**（进入结果页）
> （场景匹配跑起来，推荐 2~3 个场景，比如"图书馆三楼窗边"）

**步骤 4：展示回信卡**（点某个推荐场景，生成回信卡）
> （念回信卡上的文字，温柔一点）
- 安慰文案："今天辛苦了，找个安静的地方歇一歇吧。"
- 推荐地点：图书馆三楼窗边
- 选择原因："安静的角落，能让你快速平静"
- 小行动："找一本书翻 5 页"
- 结束语："慢慢来，一切都还来得及。" 💌

**步骤 5：收藏**（点收藏按钮）
> （显示"已收藏 ✅"）

**步骤 6：打开收藏列表**（从首页或回信卡进入）
> （展示刚才收藏的回信）

---

## 创新点说明（1 分钟）

**你**：
"这个项目的创新点主要有三个：

第一，我们做的是**情绪 → 真实校园场景的匹配**，而不是泛泛的鸡汤。
每个推荐地点都是校园里真实存在的，有具体的描述和可执行的小行动。

第二，我们把**心情、可用时间、偏好、社交舒适度**四个维度结合起来推荐。
比如同样是疲惫，只有 5 分钟和有 30 分钟，推荐的地点完全不同。

第三，我们用**「校园回信卡」**作为载体——不是弹出个"建议"，而是一张温暖的卡片，
有文案、有地点、有小行动，感觉像真的收到一封信。

而且整个项目零依赖，双击就能跑，不收集任何用户数据。"

---

## 收尾（30 秒）

> （展示 GitHub 仓库页面，指一下提交记录）

**你**：
"这是我们的 GitHub 仓库，所有人的提交记录都在这里，两天内大概有 15~20 条 commit。

完整的运行说明和安装教程在 README 里，任何人克隆下来双击 index.html 就能跑。

我们这个项目两天内从零搭起来，五个人，没有后端、没有大模型 API，
但完整实现了从情绪选择到地点推荐到回信生成到收藏反馈的闭环。

谢谢评委！"

## 备用预案

| 万一… | 预案 |
|---|---|
| 浏览器卡住了 | 提前录一个演示视频放在桌面，随时切 |
| 匹配没出结果 | 演示 data 里的 fallback 机制，展示兜底场景 |

| 评委问"数据来源" | "场景数据是我们基于真实校园地点整理的，已核实的会标记，演示的会明确标注" |
